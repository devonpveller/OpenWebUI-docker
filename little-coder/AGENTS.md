## What this codebase is

A control-plane wrapper around the upstream **little-coder** Node.js
agent. The agent runs coding tasks against an isolated workspace
(`open-terminal`); this wrapper journals every task, accumulates
craft patterns into a meta-learned skill library, and (when matured)
proposes self-improvements that the operator reviews.

Built in five chapters, gated on operator judgement:

| Chapter | Codename | What it adds |
|---|---|---|
| 1 | **Tool** | Agent + open-terminal + journals + safety controls |
| 2 | **OWUI pipeline** | Chat-shaped surface, slash-commands, founding knowledge |
| 3 | **Observer** | `meta` reads journals, clusters patterns, surfaces reports — writes nothing |
| 4 | **Learner** | `meta` drafts tier-0/1 skill artifacts under human gate; Polyglot validation; efficacy reversion |
| 5 | **Self-modifier** | Tier-0 auto-merge; tier-2 routing rules; tier-3 code changes via §11 candidate flow |

Current build state: **chapters 1–5 build-complete** apart from
operator-gated items (Polyglot corpus import, judge dry-run, etc.).
See [integration-tasks.md](../documentation/little-coder/integration-tasks.md)
"Active chapter" block for the live status.

## Core design principles (don't violate these without reading the design doc first)

1. **Knowledge first, code last.** The system's output is skill
   artifacts; code changes to the agent itself (tier-3) are rare and
   require a §6 written justification.
2. **Evidence-triggered, not time-based.** Iterations fire when new
   journal volume crosses thresholds — no clock-cadence work.
3. **Fail closed.** Judge unreachable → defer; Polyglot insufficient
   → "void", not pass; sanitization error → abort. Never "send anyway".
4. **Two planes, kept separate.** Control plane (`little-coder` container)
   decides; workspace plane (`open-terminal` container) executes. The
   boundary is the safety surface.
5. **Append-only journals.** Schema fields are unrecoverable
   retroactively. The journals are write-only from the agent's side —
   they feed `meta`, never the agent's own context.
6. **Named volumes are the persistence boundary.** Containers are
   ephemeral. All state lives on `little-coder-*` named volumes.
7. **Two knowledge layers stay distinct.** Founding knowledge
   (`agent-knowledge/`) is operator-authored and always loaded; the §7
   skill library (`little-coder-skill/`) is meta-learned and
   discovered on demand. Never let meta author founding knowledge.
8. **Locked decisions live in [integration-tasks.md](../documentation/little-coder/integration-tasks.md)** §10. If something here implies a violation of a locked decision, the docs win.

## Common workflows

### Run the full test suite

```powershell
cd little-coder
python -m pytest -q
```

### Add a new control-plane module

1. Drop the new `.py` file under [src/littlecoder/](src/littlecoder/).
   Module docstring is REQUIRED — `docs_sync` skips files without one
   and the agent-orient index goes stale.
2. Module docstring should name (a) what it does in one sentence, (b)
   the design section(s) governing it (e.g. `design §5.6`), (c) the
   chapter it belongs to (e.g. `Chapter 4`).
3. Add tests under [tests/](tests/). Match the existing patterns —
   pure-function modules get unit tests; modules with LLM/embedding
   calls use the `MockChatClient`/`MockEmbeddingClient` from
   [src/littlecoder/llm.py](src/littlecoder/llm.py).
4. Regenerate the module index: `lc admin docs sync`.
5. Flip the relevant task to `[x]` in
   [integration-tasks.md](../documentation/little-coder/integration-tasks.md)
   with a code-reference note + the design section.
6. Add a Decision Log row if the change introduced a non-obvious
   design choice (e.g. "boundary case treated as ineffective per
   §8.5 conservative read").

### Add or change a daemon HTTP endpoint

Endpoints live in [src/littlecoder/daemon.py](src/littlecoder/daemon.py)'s
`create_app(daemon)`. CLI commands live in
[src/littlecoder/cli.py](src/littlecoder/cli.py) and call the daemon via
`_request(method, path, **kwargs)`. The OWUI Pipe is a separate file
([owui/little_coder_pipe.py](owui/little_coder_pipe.py)) — re-paste it
into OWUI Admin → Functions → Little Coder when it changes.

### Add a new audit event type

Events MUST be whitelisted in [src/littlecoder/audit.py](src/littlecoder/audit.py)
or the writer raises `AuditWriteError`. Add to `TOOL_EVENTS`,
`OBSERVER_EVENTS`, or `LATER_EVENTS` depending on chapter.

### Add a new config field

Edit [src/littlecoder/config.py](src/littlecoder/config.py) (pydantic
model with `extra="forbid"`), then regenerate the committed schema:

```powershell
cd little-coder
python -c "import sys; sys.path.insert(0, 'src'); from littlecoder.config import Config; import json; print(json.dumps(Config.model_json_schema(), indent=2, sort_keys=True))" > config/little-coder.schema.json
```

A test (`test_committed_json_schema_matches_model`) fails the suite
if you forget.

### Deploy a code change

```powershell
cd "d:/Open WebUI/ai-stack"
docker compose build little-coder
docker compose up -d little-coder
```

Open-terminal also has a custom image — rebuild it separately if
you've changed [docker/Dockerfile.open-terminal](docker/Dockerfile.open-terminal):

```powershell
docker compose build open-terminal
docker compose up -d open-terminal
```

### Keep this file in sync after changes

```powershell
cd little-coder
lc admin docs sync           # update the module index
lc admin docs sync --check   # CI / pre-commit mode — exits 1 on drift
```

The auto-section is regenerated from each module's docstring; the
hand-authored sections (this one included) stay verbatim.
