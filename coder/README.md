# coder - the little-coder control plane

The self-improving coding agent. One compose project (`name: coder`,
[`docker-compose.yml`](docker-compose.yml)) of four services: a control plane
that **decides**, a workspace that **executes**, an allowlisted egress proxy,
and a backup sidecar. Keeping deciding and executing in separate containers is
the plane's safety surface. What the agent *is* - its loop, journals and skill
library, its CLI and tests - is [`../little-coder/README.md`](../little-coder/README.md);
this file is about running the plane.

Commands below run from the repository root. They are written `python`; use
`python3` if that is what your system calls Python 3.11+.

| Service | Image | Role |
|---|---|---|
| `little-coder` | `little-coder:local` | **Decides.** The daemon on `:8090` that takes work, plans, and runs the loop; owns the accumulated expertise. Prometheus metrics on `:9090`. |

| `little-coder-backup` | `alpine:3.21` | Tars five of the state volumes into `backups/little-coder` every `LITTLE_CODER_BACKUP_INTERVAL` seconds (86400), keeping `LC_BACKUP_RETAIN_COUNT` (2). |

All three `:local` images are built from [`../little-coder/`](../little-coder)
in this repository.

## Requirements

- **Docker Engine with the compose plugin, and Python 3.11+** for the driver.
- **The inference plane, enabled and serving.** `enable coder` refuses while it
  is not enabled; the agent's only model backend is the `llama-cpp` alias, and it
  needs a virtual key there (below).
- **No GPU, no sibling checkout.**

Keys, in `coder/.env`:

| Key | What happens if it is wrong |
|---|---|
| `OPEN_TERMINAL_API_KEY` | Blank, or still the shipped `change-me-...`: `enable`, `doctor` and `up` refuse. A hand-typed `docker compose` without it fails on the `${OPEN_TERMINAL_API_KEY:?}` guard rather than start a keyless executor. Define it once: a duplicate line in an env file is last-wins, silently. |
| `LC_LLAMA_API_KEY` | Not checked. The shipped `llama` is refused by the gateway with 401. Put a virtual key here ([issue one](../inference/README.md#issue-a-key-for-each-caller)). |
| `LC_ROUTE_EXEC` | Leave it `1`. `0` moves execution into `little-coder`, which bypasses both the egress allowlist and the git chokepoint - and shows up as "the clone hangs", not as a policy change. |
| `LC_DEPLOY_TOKEN` | Optional: a deploy token for cloning private repositories. |

## Enable and start

**On a fresh clone the frontend is already enabled.** With no
`.stack/state.json`, the driver treats the frontend as enabled, and `enable`
keeps it. So the `up` below starts the frontend first, and until
`frontend/.env` holds a real `WEBUI_SECRET_KEY` it stops there with
`# up stopped: frontend exited 1` and never reaches this plane. Either set up
the frontend as [its README](../frontend/README.md#enable-and-start) says, or run
this plane without it:

```bash
python scripts/stack/stack.py disable --plane frontend
```

```bash
cp coder/.env.example coder/.env
python -c "import secrets; print(secrets.token_hex(32))"
```

Put the printed value in `OPEN_TERMINAL_API_KEY=`, and a virtual key from the
inference plane in `LC_LLAMA_API_KEY=`. Then:

```bash
python scripts/stack/stack.py enable coder
python scripts/stack/stack.py up
```

The first `up` builds the three images. `little-coder` starts once
`open-terminal` is healthy.

## Operate

```bash
python scripts/stack/stack.py status
python scripts/stack/stack.py health
python scripts/stack/stack.py stats
python scripts/stack/stack.py recover coder
python scripts/stack/stack.py down coder
```

`health` probes the daemon's `/health`, which reports its own state (version,
focus, queue depth) and nothing about the executor - a dead `open-terminal`
passes it. Ask each container directly:

```bash
docker exec little-coder curl -fsS http://localhost:8090/health
docker exec open-terminal curl -fsS http://localhost:8000/health
```

Both containers' healthchecks also curl their own localhost, so they stay green
while the gateway or the virtual key is broken; a real task is the only
end-to-end test.

Restart one service with the full `-f` form:

```bash
docker compose -f coder/docker-compose.yml up -d open-terminal
```

`../little-coder/config` is mounted read-only and read at boot: restart
`little-coder` after editing `little-coder.config.yaml` or `models.json`.

**Backup and restore.** Six named volumes, `coder_little-coder-*`:

| Volume | Holds | In the sidecar's nightly tar |
|---|---|---|
| `little-coder-journals` | the journals and `audit.jsonl` | yes |
| `little-coder-skill` | the skill library | yes |
| `little-coder-cohorts` | derived counters and repro corpora | yes |
| `little-coder-polyglot` | the Polyglot benchmark clone | yes |
| `little-coder-sessions` | one session file per chat or CLI channel | yes |
| `little-coder-workspace` | the project clone, shared with `open-terminal` | no - switching project wipes and re-clones it |

`python scripts/stack/stack.py backup coder` archives all six on demand, taking
a live copy while the plane runs. To restore:

```bash
python scripts/stack/stack.py down coder
python scripts/stack/stack.py restore coder --from backups/coder/manual-<UTC stamp>
python scripts/stack/stack.py up
```

Check the newest tarball in `backups/little-coder`, not the sidecar's exit code:
its script exits 0 when there is nothing to archive.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `refused: coder requires inference, which is not enabled` | Enable the inference plane first: `python scripts/stack/stack.py enable --plane inference`. |
| `refused: coder cannot be enabled yet:` naming `OPEN_TERMINAL_API_KEY` | Set it in `coder/.env`. |
| 401 from the gateway in `docker logs little-coder` | `LC_LLAMA_API_KEY` is not a virtual key the gateway issued. |
| `network ai-stack_llm-net declared as external, but could not be found` from a hand-typed `docker compose` | The anchor's networks are missing; `python scripts/stack/stack.py up` creates them. |
| `[DIFFERS] ai-stack_llm-net: internal is false, declared true` and `up` stops | An existing network does not match the anchor. Stop what is attached, `docker network rm ai-stack_llm-net`, run `up` again. |
| A clone from a forge other than GitHub hangs or fails like a network flake | `lc-egress` allows only `github.com` and `githubusercontent.com`. Add the host to `little-coder/docker/egress-allowlist.txt` and rebuild `lc-egress` (`docker compose -f coder/docker-compose.yml build lc-egress`, then `up -d lc-egress`); the list is baked into the image, so a restart does not pick it up. |
| `docker compose up -d open-terminal` at the repository root prints `no such service: open-terminal` | The root project declares networks only. Use `-f coder/docker-compose.yml`. |
| `ConvertFrom-Json` fails with `DuplicateKeysInJsonString` on this plane's render | Windows PowerShell 5.1 reads JSON keys case-insensitively and the plane sets both `HTTP_PROXY` and `http_proxy`. Read the render as YAML. |

## Security notes

- **It bounds accidents, not a hostile repository.** Inside `open-terminal`,
  `git` is a wrapper; the real binary is `/usr/bin/git.real`, and hooks a cloned
  repository brings are never run. But `open-terminal` runs as root and the
  workspace volume is writable from both containers, so a determined process can
  still reach `.git/config`. Point this plane at repositories you trust.
- **Egress.** `open-terminal`'s networks are both internal; its only way out is
  `lc-egress`, which allows `CONNECT` to ports 443 and 22 for the allowlisted
  hosts only. `little-coder` has no internet at all. `lc-egress` is up whenever
  the plane is.
- **One published port**: `127.0.0.1:9091`, metrics, loopback. `little-coder:8090`
  accepts work and `open-terminal:8000` executes commands; neither is published.
  Open WebUI's little-coder pipe reaches the daemon by name on `ai-stack_llm-net`.
- **Rebuilding here changes what agent-org runs.** Its worker pool uses
  `little-coder:local` and `little-coder-open-terminal:local`, and its egress
  services build `little-coder-egress:local`, none pinned by digest. A plain
  `up -d` never rebuilds an existing image; keep it that way unless the retag
  is what you mean.

## Changing this plane

Adding, removing or moving a container is never a one-file change; the
checklist is
[`SERVICE-LIFECYCLE.md`](../documentation/runbooks/SERVICE-LIFECYCLE.md). The
places this plane appears:

- [`docker-compose.yml`](docker-compose.yml) and
  [`../little-coder/`](../little-coder) (the images and the config).
- The agent's context window comes from `../little-coder/config/models.json`,
  and `LITTLE_CODER_NO_CTX_PROBE=1` is deliberate: the gateway does not forward
  llama.cpp's `/props`. Keep the declared window under the model's per-request
  share of the llama.cpp context (`ctx-size / n_parallel`).
- [`../stack.manifest.toml`](../stack.manifest.toml): `[planes.coder]` and the
  `coding-agent` product.
- `scripts/stack/stack.py`: the coder probe in `HealthSweep.run()` and its label
  in `PS1_PROBES` (`scripts/stack/test_stack.py`).
- `scripts/recovery/emergency-recovery.ps1`, `scripts/checks/stack-watchdog.ps1`
  and `scripts/checks/check-backup-coverage.ps1` (which records the workspace
  volume's exemption from backup).
- `scripts/lib/stack-services.curated.json`, then
  `python scripts/stack/stack.py inventory --write`.
- `.claude/skills/stack-map/references/workspace-stacks.md`,
  `documentation/CONTAINER-REGISTRY.md`,
  [`restore-from-snapshot.md`](../documentation/runbooks/restore-from-snapshot.md),
  and the `coder` lease in `scripts/agent-harness/lease-names.conf`.
- Inference goes through the `llama-cpp` alias only;
  `scripts/checks/check-llm-gateway-routing.ps1` enforces it at commit time.

Then run `python scripts/stack/stack.py docs --check` and `/stack-map`.
