## 0. Working agreements (read before touching anything)

These hold for **every** task. They are the parts an autonomous run is most likely to get wrong.

- **G1 — Never `git add`/`commit`/`push` on the operator's behalf** ([git-handling-boundaries](../../../../../Users/yamao/.claude/projects/d--Open-WebUI-ai-stack/memory/git-handling-boundaries.md), plan §11). The **one** exception: the workbench's *own programmatic commits inside the vault repo* (that **is** the notes write mechanism, P3) — local only, **no remote push** until the self-hosted vault exists (D-I). You, the coder, still never commit the repo you are editing.
- **G2 — Additive schema only** (plan §11). Never `ALTER`/`DROP` an existing `thoughts`/`sources` column. Widening a CHECK = drop-and-re-add with values only **added**. New columns are `ADD COLUMN IF NOT EXISTS … DEFAULT …`.
- **G3 — Every new SQL file ships in *two* places** (plan §7 ⚠ migration). `/docker-entrypoint-initdb.d` runs **only on a fresh `openbrain-db-data` volume** ([docker-compose.yml:36-37](../../../OB1/docker/docker-compose.yml#L36-L37)). So each new `.sql` must be **(a)** mounted with an ordering prefix *after* `70-init-threads.sql` (`80-…`, `90-…`, `95-…`) for fresh installs **and (b)** applied to the **live** DB via the psql promotion runbook. A file only added to compose **silently no-ops on the running stack.**
- **G4 — Three-place change convention** (CLAUDE.md, plan §11). Adding/removing a container (`openbrain-workbench`, `openbrain-extract`) means editing **together**: the compose file, the recovery scripts' inventory **and** ordered start/stop sequences ([scripts/emergency-recovery.ps1](../../../scripts/emergency-recovery.ps1) + `.bat`), and the stack-map ref ([workspace-stacks.md](../../../.claude/skills/stack-map/references/workspace-stacks.md)). Run the `/stack-map` skill before and after compose edits to catch drift. Marked 🔁 below.
- **G5 — One shared slug module** (plan §12.12, §14.1). Do **not** add a 4th/5th copy of `slugify`. Extract `slug.mjs`/`slug.ts` (canonical = the NFKD-normalize → lowercase → `[^a-z0-9]+`→`-` → trim algorithm) **in P0** (task 0.6 below) and import it from the recipe, the compiler, and the workbench. A drifting slug fn silently breaks `[[wikilink]]` resolution across layers.
- **G6 — Pinned slugs** (plan §14.2). Notebook (`threads.slug`) and entity slugs are generated **once at create time** and **never recomputed**. Rename touches the display `name` only; pages emit `aliases: [name]` so old links resolve. De-collide on the `UNIQUE` violation (`-1`/`-2`, mirroring [`resolveOutputPath`](../../../OB1/recipes/entity-wiki/generate-wiki.mjs#L815)).
- **G7 — Secret stays server-side** (plan §2.3, §12.6). A static Quartz page **cannot hold a bearer.** Never embed `MCP_ACCESS_KEY`/`WORKBENCH_KEY` in client JS. Caddy **injects** `header_up X-Brain-Key {$WORKBENCH_KEY}`; the workbench trusts that header on `app-net` and is **never host-published** (debug publish to `127.0.0.1` only).
- **G8 — Workbench writes are transactional** (plan §14.5). Multi-row writes (import = source + chunks + links) go through **deno-postgres with a transaction** (precedent: `openbrain-suggestion-worker`, [docker-compose.yml:299-325](../../../OB1/docker/docker-compose.yml#L299-L325)). Reads may use PostgREST. Never fire several non-atomic PostgREST writes for one logical unit.
- **G9 — Workbench is sub-routered, not a god-switch** (plan §14.3). Hono sub-routers per resource (`/sources`, `/threads`, `/notes`, `/import`, `/notebooks`, `/grounding`) over a thin **service → repository** layering. Path/asset normalization (no `../` escape) lives in **one shared validator** (§14.3, §11), not per-handler.
- **G10 — Validation is a sandbox/dev concern.** Do not test against prod volumes. Stand validation on a throwaway DB volume; never run a destructive migration against the live `openbrain-db-data` without the operator running the promotion runbook.
- **G11 — Retract (P4) and grounding (P6) are *staged mutations*** (plan §4, §12.14). A state change **never hits the rendered view piecemeal**: a live "in progress / pending" marker propagates to **every** reference instantly (hydrated, no compile), the rendered effects land **all at once** at the compile tick, and there is a **reversal window** before commit during which reversing **regenerates nothing and leaves no orphan**. Commit is **autonomous** — requesting the change and *not cancelling during the staging window* **is** the confirmation (no "Apply" button). The safety mechanism is **visibility of effects**: a **gravity counter** at request time (*"linked to N notebooks, cited on M pages"*) + a **`Changes` log** written into the author-owned `notes/` layer (outside the generation pool). Durable staging state (`sources.retraction_committed_at`; `import_jobs.staged/committed`) **must survive a workbench restart**. **Exception: purge is NOT staged** — it is irreversible and always needs an explicit confirm. See the [Staged mutations](#staged-mutations-p4-retract--p6-grounding--shared-lifecycle) block below.
- **G12 — Frontmatter id contract** (plan §3 P0.6). Every hydrated page class bakes a **stable backing id** into its frontmatter: **entity pages** → `entity_id` + `wiki_slug`; **notebook hubs** → `thread_id` + `slug`; **leaf pages** → `type` + `id`. Hydrated client components (P6 grounding badge, `SourceLinker`, `NotebookPage.inline.ts`) key off these fields — **never** off URL-parsing or guessing. Lands in P0 (task 0.8) because P2/P6 silently depend on it.

## Staged mutations (P4 retract & P6 grounding) — shared lifecycle

*Plan §4, §12.14 — read before P4/P6.*

Both **retract** (P4) and **ground-from-the-page** (P6) are *staged mutations* (G11). Written once here, referenced from P4 and P6. **Commit is autonomous — no "Apply" button**; requesting the change and not cancelling it during the staging window **is** the confirmation. Safety = **visibility of effects**, not a click:

- **Gravity counter** at request time — *"linked to N notebooks, cited on M wiki pages"* — so scope is legible at the moment of acting.
- **`Changes` log** written into the author-owned `notes/` layer (outside generation scope): a programmatically generated page illustrating each staged change's effect + logging the user's action (what changed, when, which links are affected). Durable, human-readable, never in the generation pool.
- The user can therefore grasp the effect *after the fact* (open affected links / the `Changes` log) and **reverse the stage before the compile commits** it.

**Lifecycle — retract:** (1) retract → `retracted_at` set, `retraction_committed_at` NULL (= **staged**, reversible). (2) **Instantly (hydrated, no compile):** every reference — citing entity pages, the `source/<uuid>` leaf, notebook-hub source lists — shows a live **"redacted source — `in progress`"** marker. (3) **Reversal window:** clearing `retracted_at` before commit makes markers vanish on next hydrate; nothing regenerated, no orphan leaf, no wasted compile. (4) **Commit (autonomous, at the compile tick draining the change):** the source enters the generation-exclusion read-paths (P4.5 checklist), the leaf is swept, citing pages regenerate with the citation gone — all at once.

**Lifecycle — grounding:** (1) ground (upload/URL) → source ingests via the P5 `/workbench/import` route → `source_entities` link lands → badge hydrates **"⏳ Grounding pending."** (2) **Staged, held:** the entity is *marked* to regenerate, but the regenerated body + "Grounded by N" badge are **held** until compile completes (not trickled in). (3) **Reversal window:** removing the staged link before compile reverts cleanly — no half-regenerated page. (4) **Commit (autonomous, at compile completion):** the badge flips to **"Grounded by N"** at the *same moment* the regenerated body goes live — never before.

**Durable staging state (must survive a workbench restart):**
- Retract: `retracted_at` + **`retraction_committed_at TIMESTAMPTZ`** (NULL = staged/reversible; set = committed). Generation read-paths exclude only `retraction_committed_at IS NOT NULL`; the live "in progress" marker keys on `retracted_at IS NOT NULL AND retraction_committed_at IS NULL`.
- Grounding: `import_jobs` gains a **`staged`/`committed`** distinction; the badge reads pending-vs-grounded from job state + the compile watermark; a pull cancels the job and removes the staged `source_entities` row.

**Tombstone visibility contract (D-D):** a retracted source is, throughout its life — **excluded from the future generation pool** (every read-path filters it, P4.5 checklist) · **retained always** (row + content survive, restorable) · **visible-but-marked** wherever still referenced · **UX-hidden once it has no remaining links** (unreachable, though the row persists). Retract is *eventually consistent* on the read surface **by design** — the "in progress" wording makes the transient state legible, not a bug. **Purge is NOT staged** — irreversible, always explicit-confirm.

## Audit-critical items to keep front-of-mind (plan §11, §14, inline ⚠)

1. **Leaf sweep ≠ entity sweep (1.5).** Reusing `sweepOrphanEntityPages` deletes **every** `thought/`+`source/` leaf on the next compile. Needs the skip-list addition **and** a new `sweepOrphanLeafPages`. Same bug-class for the notebook hub (2.3).
2. **Source citations are UUIDs, not ints (1.3/1.4).** Regex must match 36-char hyphenated UUIDs; never make the LLM echo a UUID — use the `S1/S2…`→UUID per-page token map. Thought ids (`BIGSERIAL`) stay literal.
3. **Tombstone filtering is a *checklist*, not one edit (4.5).** Six read-paths must filter **`retraction_committed_at IS NOT NULL`** (NOT `retracted_at` alone — that would pull a *staged* retract out of generation before its reversal window closes). Miss one → retracted sources resurface in generation.
4. **`source_entities` has no `metadata` column (6.3).** Use `mention_role='user_linked'`; PK is `(source_id,entity_id)`; `user_linked` wins on collision.
5. **The worker wipes `source_entities` per source (6.4).** Without the `.neq("mention_role","user_linked")` scope, every manual grounding link is deleted on the next re-extraction.
6. **New SQL must hit *two* places (G3).** initdb mount (fresh) **and** the live-DB promotion runbook. Compose-only = silent no-op on the running stack.
7. **`content_type` migration order on the live DB (5.2).** create → seed existing+new values → drop CHECK → add FK. FK-add fails on any unseeded value.
8. **Secret never reaches the browser (G7).** Caddy injects `X-Brain-Key`; workbench is never host-published; client JS holds no bearer.
9. **Caddy edit is the *portal* `wiki.` block, not OB1/docker/Caddyfile (0.2).** The OB1 Caddyfile only fronts internal PostgREST.
10. **Don't suppress graph pages (6.1/6.5).** Badge thought-only pages as "ungrounded belief"; never delete them — that breaks cross-entity `[[wikilinks]]` and graph nodes.
11. **Retract & grounding are STAGED, commit autonomously (G11, §Staged mutations).** Durable staging state (`sources.retraction_committed_at`; `import_jobs.staged/committed`) must survive a workbench restart; the live "in progress/pending" marker propagates to **every** reference instantly (hydrated), effects land **all-at-once** at the compile tick, and a reversal before commit must regenerate nothing + leave no orphan. No "Apply" button — safety is the gravity counter + `Changes` log. **Purge is the exception: not staged, always explicit-confirm.**
12. **Frontmatter id contract (0.8 / G12).** Hydrated components key off baked frontmatter ids (`entity_id`/`thread_id`/leaf `id`), **never** URL-parsing. Lands in P0 because P2/P6 silently depend on it.
13. **Update is never replace (4.2).** The source UI exposes **no "replace" affordance** — only "update this source / record a revision" (+ URL re-fetch) and a separate "add new source". A replace gesture teaches the wrong mental model.
14. **Triaged links stay triaged (2.5).** A user-`hidden`/`inactive` `thread_sources` link must suppress re-suggestion — the worker must not re-propose a pair the user rejected (symmetric to `user_linked`-wins in 6.4).
