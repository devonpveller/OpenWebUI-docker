# scripts/archive/

Retired operational code, kept for history and provenance. Nothing in this
directory is referenced by any live path — compose files, scheduled tasks,
hooks, recovery scripts, or modules. Each subdirectory notes what retired it.

| `legacy-recovery/` | 2026-09-25 | adoption-closeout `ac-legacy-recovery`. From `scripts/recovery/`: `quick-fixes.bat`, `update-stack.bat` and five Python helpers (`namespace_reset.py`, `gpu_check.py`, `restart_openwebui.py`, `rebuild_tailscale.py`, `nuclear_option.py`); from `scripts/checks/`: `dev-helper.ps1`. The fault common to seven of the eight (all but `namespace_reset.py`, see below): a `docker compose <verb>` with no `-f`, run in the repo root, addresses the root anchor project, which has had zero services since Part K.5b (2026-08-21). A service verb then exits `no such service`, a root `up -d` exits `no service selected`, and a root `down` can remove the anchor's networks. Per script (line numbers are in the archived copies): **`quick-fixes.bat`** runs each compose call after `cd /d "%SCRIPT_DIR%\..\.."`, the repo root (e.g. line 79), so its `-f <plane>` calls worked - `namespace` (line 87) really restarted tailscale. What was broken: `nuclear` is a root `down` (186), which can remove any anchor network no container holds, and a root `up -d` (190), which starts nothing (`no service selected`); `rebuild` begins with a bare `down tailscale` (120); `status` runs a bare `ps` (335); `restart-openwebui` stops the frontend with `--timeout 45-backup` (472; compose rejects it: `invalid argument "45-backup"`), tries a bare `start` six times (492-541) before each `-f ... up -d` fallback, and ends on a bare `ps` (550); `status` and `openbrain` call `%SCRIPT_DIR%check-openbrain-health.ps1` (445, 760), and that file is in `scripts/checks/`, not `scripts/recovery/`; and `gpu` restarts openwebui without tailscale (227), which is against the netns rule. What still worked duplicates `emergency-recovery.ps1` and `stack.py`. **`update-stack.bat`** also runs from the repo root (68), and none of its compose calls names a file. **Four of the five Python helpers** (`gpu_check.py`, `restart_openwebui.py`, `rebuild_tailscale.py`, `nuclear_option.py`) find their root by walking up to the first `docker-compose.yml` (`find_project_root()`, e.g. `gpu_check.py` 29-50), which is the anchor, and issue bare compose verbs there (e.g. `gpu_check.py` 78, `nuclear_option.py` 127 and 144). `quick-fixes.bat` never called any of the five: its `:gpu_check`-style names are its own labels. Their last caller was the OWUI emergency-recovery module (`scripts/archive/emergency-recovery-module/service/emergency_recovery.py` 42-47), which was archived 2026-08-20, so they had been orphaned since then. `namespace_reset.py` issues no compose call at all. Its defect is that it fixes nothing: it checks a socket, prints a bare `docker compose restart tailscale` as advice (173), and returns 0 (174). It is archived as an orphan with the other four. **`dev-helper.ps1`** runs in the repo root (13) and validates with a bare `config` (63), which checks only the anchor and reports it valid; its rebuild is a bare `build tailscale` (102). Replaced by: `scripts/recovery/emergency-recovery.ps1 -Action recover|gpu-reset|nuclear` (namespace, GPU, nuclear), `scripts/recovery/status_check.py` and `python scripts/stack/stack.py health` (status and the per-service checks), `python scripts/stack/stack.py restart frontend` (restarts openwebui and tailscale together), per-plane `docker compose -f <plane>/docker-compose.yml pull/build/up -d` as `documentation/runbooks/UPDATE-MANAGEMENT.md` describes (updates, a deliberate tailscale rebuild), and the pre-commit `validate-lineendings.ps1` / `check-project-configs.ps1` (dev-helper's checks). No scheduled task, status-pipe module, sysadmin-mcp tool or Telegram command called any of them at retirement (`Get-ScheduledTask` actions and `git grep` of every tracked file, 2026-09-25). |
