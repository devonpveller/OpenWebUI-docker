# identity-allowlist.txt - what scripts/checks/check_identity.py lets stay, and why.
#
# One entry per line:   <path glob> | <class>[~<context regex>] | <reason>
#   path glob   repo-relative, `/` separators; `**` crosses directories, `*` does not
#   class       lan-ip, tailnet-ip, tailnet-host, user-profile-path, drive-host-path,
#               email, operator (a literal from the LOCAL denylist - never named here)
#   ~regex      optional. The finding is allowed only if it lies INSIDE a match of this
#               regex on its line - so an entry can allow "the owner segment of a URL to
#               this project's own repository" without allowing the same value anywhere
#               else on that line, and without spelling it.
#   reason      required: why it must stay rather than be parameterised or generalised.
#
# THIS FILE IS SCANNED LIKE ANY OTHER. An entry that spelled a guarded value would itself
# be a finding, so write shapes, never values. Prefer fixing over listing: a variable in
# the owning plane's .env (generic value in its .env.example), or generic prose (<user>,
# example.com, 192.0.2.10). `check_identity.py --all` prints entries that match nothing
# as STALE; remove them.
