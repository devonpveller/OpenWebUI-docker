# frontend - Open WebUI

The chat interface. One compose project (`name: frontend`,
[`docker-compose.yml`](docker-compose.yml)) holding Open WebUI, its backup
sidecar and, optionally, a Tailscale node that shares Open WebUI's network
namespace. It is the plane a fresh clone runs: `stack.py init` with no
arguments enables this plane and nothing else.

Commands below run from the repository root. They are written `python`; use
`python3` if that is what your system calls Python 3.11+.

| Service | What it is |
|---|---|
| `openwebui-stock` | Open WebUI on the pinned upstream image `ghcr.io/open-webui/open-webui:v0.11.0` (override with `OWUI_IMAGE`). No build, no GPU, and no network shared with any other plane. |
| `openwebui` | The same Open WebUI release built locally with CUDA torch ([`Dockerfile.openwebui-gpu`](Dockerfile.openwebui-gpu), image `openwebui:local`), with an NVIDIA device reservation, the anchor networks that reach the other planes, and read-only mounts of [`status-pipe/`](status-pipe/README.md) and [`system-prompts/`](system-prompts/). |

| `tailscale-backup` | The same loop for `data/tailscale`, into `backups/tailscale`. |

The profile is chosen by the `COMPOSE_PROFILES` line in `frontend/.env`, and
exactly one of three values is useful:

| `COMPOSE_PROFILES` | You get |
|---|---|
| `stock` (what `.env.example` ships) | Open WebUI alone. Runs on any machine with Docker. |
| `gpu` | Open WebUI with CUDA, attached to the other planes' networks. |
| `gpu,tailscale` | The above plus the tailnet node. |

`stock` and `gpu` both define the container `openwebui` on port 3000 and the
volume `frontend_openwebui-data`, so a machine can move between them and keep
its data - but never run both. `tailscale` cannot run without `gpu`.

## Requirements

- **Docker Engine with the compose plugin, and Python 3.11+** for the driver.
- **Under `stock`: nothing else.** No GPU, no other plane, no sibling checkout.
- **Under `gpu`:** an NVIDIA GPU with the NVIDIA Container Toolkit, and the
  time and disk to build `openwebui:local` locally (the Dockerfile installs
  CUDA torch). `GPU_AISTACK_DEVICE_ID` picks the device.
- **Under `tailscale`:** a Tailscale auth key.

Keys, in `frontend/.env`:

| Key | When | What happens if it is wrong |
|---|---|---|
| `WEBUI_SECRET_KEY` | always | Blank or still `change-me-...`: `init`, `enable`, `doctor` and `up` refuse, naming it. It encrypts secrets at rest in `webui.db` and signs sessions, so **set it once and keep it** - changing it later breaks every stored connection secret and logs everyone out. |
| `OWUI_CHAT_LLM_API_KEY` | `gpu` | Still the shipped `sk-change-me-...`: `doctor` and `up` refuse. A LiteLLM virtual key issued by the inference plane (see [`../inference/README.md`](../inference/README.md#issue-a-key-for-each-caller)), used by the Server Status pipe. Never the master key. |
| `TAILSCALE_AUTH_KEY` | `tailscale` | Still the shipped `putyourtskeyhere`: `doctor` and `up` refuse. A blank or expired key is not caught - the node starts and cannot join the tailnet. |

**Other planes.** None is required. Under `stock` Open WebUI is on its own
network and reaches nothing else in the stack: it has no model until you add a
connection yourself in Admin Settings. Under `gpu` it reaches, by service name,
the inference plane (`llama-cpp`), the search plane (`gateway`, for web search),
and - through the tailnet routes - Open Notebook, the portal's Caddy, the
LiteLLM Admin UI and Mattermost. Each of those is optional: the route or
feature is dead while its plane is off, and chat still serves.

## Enable and start

```bash
cp frontend/.env.example frontend/.env
python -c "import secrets; print(secrets.token_hex(32))"
```

Put the printed value in `frontend/.env` as `WEBUI_SECRET_KEY=...`, then:

```bash
python scripts/stack/stack.py init
python scripts/stack/stack.py up
```

`init` writes `.stack/state.json` enabling the frontend alone. `up` creates the
three shared `ai-stack_*` networks if they are missing, then starts the plane;
it pulls the Open WebUI image the first time. Open `http://127.0.0.1:3000` - the first
account you create is the administrator.

To see what `up` would run without running it:

```bash
python scripts/stack/stack.py up --dry-run
```

To move to `gpu` or `gpu,tailscale`, change the `COMPOSE_PROFILES` line in
`frontend/.env`, fill in the keys the table above names for that profile, and
run `python scripts/stack/stack.py up` again. Under `gpu`, `up` builds `openwebui:local` if
the image is not on the machine yet. After that a plain `up` never rebuilds it; rebuild only on
purpose, following
[`UPDATE-MANAGEMENT.md`](../documentation/runbooks/UPDATE-MANAGEMENT.md).

## Operate

```bash
python scripts/stack/stack.py status             # docker compose ps for the enabled planes
python scripts/stack/stack.py health             # probes; the exit code is the number that failed
python scripts/stack/stack.py stats              # CPU / memory / network per container
python scripts/stack/stack.py recover frontend   # ordered stop and start, every container gated
python scripts/stack/stack.py down frontend
```

`health` checks `http://127.0.0.1:3000/health`; under `tailscale` it also
counts the eight serve routes. The drift check between [`owui/`](owui/README.md)
and the live database needs PowerShell, and prints `[skip]` where there is none.

**Backup and restore.** `openwebui-backup` writes a nightly tar of the data
volume into `backups/openwebui`. For a copy on demand, and to restore one:

```bash
python scripts/stack/stack.py backup frontend
python scripts/stack/stack.py down frontend
python scripts/stack/stack.py restore frontend --from backups/frontend/manual-<UTC stamp>
python scripts/stack/stack.py up
```

`backup` writes `backups/frontend/manual-<UTC stamp>/` with one `.tar.gz` per
named volume, a `manifest.json` and `SHA256SUMS`. It works while the plane runs
and records that the copy was taken live (`webui.db` may be mid-write).
`restore` checks every checksum first and refuses while a container still holds
the volume - hence the `down`. The restore stages the archive before replacing
anything, so it needs free space for the old contents and the new at once.
`data/tailscale` is a host directory, not a volume: `backup` counts it and
leaves it to you.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `init` prints `refused: that state file would not work yet`, or `up` prints `refused: fix these before` ..., naming `WEBUI_SECRET_KEY` | A key is blank or still its shipped value. Set it; nothing was started. `python scripts/stack/stack.py doctor` lists every such key. |
| `refused: .stack/state.json already exists (re-run with --force to overwrite it)` | `init` never overwrites. Use `enable <plane>` to add to the file; `init --force` replaces it and drops every plane it named. |
| `[DIFFERS] ai-stack_llm-net: internal is false, declared true` and `up` stops | A network of that name exists and does not match the anchor's declaration. The driver never alters an existing network: stop what is attached to it (`docker network inspect ai-stack_llm-net`), `docker network rm ai-stack_llm-net`, and run `up` again. |
| `up` starts `openwebui-backup` and nothing else | `COMPOSE_PROFILES` is missing from `frontend/.env`. With no profile, `down` also leaves `openwebui` running, and any compose command naming `tailscale` fails with `no such service: openwebui`. |
| `container name "openwebui" is already in use` | `COMPOSE_PROFILES` names both `stock` and `gpu`. Pick one. |
| `service "tailscale" depends on undefined service "openwebui"` | `tailscale` without `gpu`. Use `gpu,tailscale`. |
| The tailnet stops answering after Open WebUI was restarted | `tailscale` lives in `openwebui`'s network namespace. Restarting `openwebui` alone leaves `tailscale` attached to a namespace that no longer exists. Restart the pair in order - `python scripts/stack/stack.py recover frontend` does, and refuses a plan that would restart `openwebui` without `tailscale` after it. |
| No models in the model picker | Under `stock` there is no route to the inference plane; add a connection in Admin Settings, or move to `gpu`. Under `gpu`, the inference plane must be up and Open WebUI's connection must carry a LiteLLM virtual key. |
| `restore` refused: `in use by openwebui, openwebui-backup` | Run `python scripts/stack/stack.py down frontend` first. |

## Security notes

- The only published port is `127.0.0.1:3000`, loopback. Reach it from other
  machines through the tailnet or the portal plane, not a LAN bind.
- Under `gpu` the container mounts `status-pipe/`, `system-prompts/` and
  `data/tailscale` read-only and nothing else from the repository; no `.env` or
  secret file is visible inside it.
- `OWUI_CHAT_LLM_API_KEY` is a low-privilege virtual key. The LiteLLM master key
  never belongs in this plane.
- Open WebUI can fetch URLs on a user's behalf (document loaders, web search),
  and `openwebui-backup` installs `pigz` from the Alpine mirror at every start,
  so this plane reaches the internet under either profile.
- Plugins in [`owui/`](owui/README.md) are pasted into the running instance;
  read one before deploying it - several make network calls of their own.

## Changing this plane

Adding, removing or moving a container is never a one-file change; the
checklist is
[`SERVICE-LIFECYCLE.md`](../documentation/runbooks/SERVICE-LIFECYCLE.md). The
places this plane appears:

- [`docker-compose.yml`](docker-compose.yml) and the build inputs beside it
  ([`Dockerfile.openwebui-gpu`](Dockerfile.openwebui-gpu),
  [`dockerfile.tailscale`](dockerfile.tailscale), [`entrypoint.sh`](entrypoint.sh),
  `.dockerignore`). The services share blocks declared once as YAML extension
  fields (`x-hardening`, `x-hardening-owui`, `x-healthcheck-http`,
  `x-backup-sidecar`) and merged with `<<:`. A merge key merges maps; a list
  written on a service REPLACES the anchored list, so a service needing one more
  `security_opt` or `tmpfs` entry spells out the whole list.
- [`status-pipe/`](status-pipe/README.md), [`system-prompts/`](system-prompts/)
  and [`owui/`](owui/README.md), which `.dockerignore` keeps out of both build
  contexts.
- [`../stack.manifest.toml`](../stack.manifest.toml): `[planes.frontend]`, its
  profiles, and the `chat` product.
- `scripts/stack/stack.py`: the frontend probes in `HealthSweep.run()` and the
  labels pinned in `PS1_PROBES` (`scripts/stack/test_stack.py`).
- `scripts/recovery/emergency-recovery.ps1`, `scripts/checks/stack-watchdog.ps1`,
  `scripts/checks/check-watchdog-repair-targets.ps1` and
  `scripts/backup/restore-from-snapshot.ps1` (the `openwebui` and `tailscale`
  entries).
- `scripts/lib/stack-services.curated.json`, then
  `python scripts/stack/stack.py inventory --write`.
- `.claude/skills/stack-map/references/workspace-stacks.md`,
  `documentation/CONTAINER-REGISTRY.md`, the backup and restore runbooks, and
  the `frontend` lease in `scripts/agent-harness/lease-names.conf`.

Then run `python scripts/stack/stack.py docs --check` and `/stack-map`.
